## 1. 这次要做成什么

知养是一款以中药养生知识和传统食养理论为基础，结合可核对的营养与健康知识，面向各类健康问题提供分层回应的 AI 食疗养生助手。输出以日常饮食、食养茶饮、起居和身心调养参考为主。用户可以从健康知识、身体感受、基础病相关食养需求或生活目标开始交流，也可以先浏览内容。

首版允许用户自由提出健康问题，通过必要追问与需求澄清，决定提供知识解释、生活建议、可修改的食养安排，或专业求助提示。对于适合形成安排的需求，用户可以保存、替换并在下次继续调整；并非每个问题都必须输出食谱或茶饮。

保留现有“首页、食养、调养、我的”四个页面。首页继续突出 AI 咨询，同时保留三餐起居、茶饮、调养专题和文章。用户不必先完成体质测评或填完一大套档案才能开始使用。

产品提供日常生活与食养参考。基础病患者、老年人、孕哺期人群及婴幼儿的照护者均可以咨询，不因人群标签一律拒答。疾病诊断、调整治疗与用药、自主开具治疗性营养处方或中药处方不属于本轮范围；与基础病有关的一般食养知识可以有依据地回答，具体方案需结合相关限制。问题涉及疾病不等于必须拒答，回答被称为“养生”也不等于它自动不涉及医疗。

风险控制是首要约束。明确紧急情况直接提示与紧急程度匹配的专业帮助，必要时立即联系当地急救服务或就近急诊，本轮不提供任何调养方案、用药或居家处理步骤。特殊人群和特殊情况下，必要信息或依据不足时不输出个人方案。目标是尽量降低风险，不承诺“零责任”或“规避一切风险”；免责声明不能替代实际限制，相关说明见健康规则。

## 3. 服务人群与主要问题

服务对象是有食疗养生与身心调养需求的广泛人群，包括一般健康用户、有基础病的人、老年人，以及孕哺期人群和婴幼儿的照护者。减重、增重只是使用场景。具体年龄、状态、用药及问题类型影响回答方式，不用一个人群标签直接决定“可以问／不可以问”。婴幼儿相关问题由监护人或照护者描述。首轮测试样本的选择不等同于长期服务人群边界。

| 用户的原话或近似表达 | 实际需要完成的事情 | 当前常见困难：待访谈验证 |
| --- | --- | --- |
| “最近胖了，三餐应该怎么吃？” | 获得符合外食或做饭条件的饮食搭配，能替换不喜欢的食物 | 知道原则，但不清楚怎样放进每天的三餐 |
| “我比较瘦，想把饭吃好一点。” | 查看完整三餐与可选加餐，结合食欲、习惯和时间调整 | 容易把增重理解为只加一种食物，难以形成日常安排 |
| “想喝点养生茶，应该怎么选？” | 看懂原料、准备方式、适用说明，再选择一个明确的饮品 | 内容分散，风味、传统说法和功效容易混在一起 |
| “总觉得湿气重／嗓子不舒服／排便不顺。” | 说清具体感受，了解日常照护参考和何时需要专业帮助 | 不知道从哪类内容查起，也可能把养生内容当治疗 |
| “这顿我做不了，换一个。” | 保留自己的目标和已有安排，只调整做不到的部分 | 每次需要重新交代情况、重新整理回答 |
| “我头痛怎么办？” | 澄清症状、相关背景与紧急程度，了解适当下一步；适合时再聊生活安排 | 既不希望被机械拒绝，也不应被直接引向一杯茶 |
| “我有基础病，日常吃什么需要注意？” | 结合已确诊情况、现有医嘱及相关限制理解食养原则 | 通用建议可能遗漏已有疾病、用药和膳食限制 |

对于基础病相关咨询，可以解释有依据的一般食养原则，并在信息和已审核内容足够时帮助落实符合已知限制的日常安排。涉及治疗性目标、复杂合并症或未核实的药食相互作用时，继续提供必要解释、澄清与专业求助提示，不凭空补出配方。不能因为用户提到“想减重”就认定其需要减重。

首页默认内容是精选的一般参考。只有确实使用了用户信息时，才标注“结合你的偏好”；时间、日期和时令信息不能继续使用 Demo 的固定日期伪装为实时推荐。

内容详情统一包含：名称、内容类别、原料或准备条件、具体做法／安排、可替换项、适用说明、参考来源及审核状态。餐食和茶饮不使用同一套含糊的功效标签。

## 7. 核心使用流程

### A. 从问题到一份三餐安排

1. 用户在首页选择减重、增重或三餐搭配，也可以自己输入。
2. 助手了解目标和缺失的关键条件，例如做饭／外食、能投入的时间、饮食偏好与相关限制。已经知道的信息不重复问；普通生活偏好允许跳过。
3. 如果涉及是否适合调整体重等关键情况尚不明确，先提供一般搭配参考，不直接设置个人热量或体重目标。
4. 展示早餐、午餐、晚餐；有需要时另列加餐。说明所采用的条件，并提供具体食养内容入口。
5. 用户说“午餐换一个”“不要鱼”“买不到这个”，只替换相关部分，同时说明换了什么。
6. 用户主动保存后，“我的方案”出现对应安排。普通聊天回答不会自动变成已保存方案。

### B. 从茶饮内容到适合自己的选择

1. 用户进入茶饮详情，或向助手提出饮品需求。
2. 结合用户偏好和相关限制，从本轮已经审核的固定饮品条目中选择。
3. 展示原料、准备方式、引用依据与适用说明。AI 可以解释已有内容，不自由增加药材、用量或治疗功效。
4. 没有合适条目或缺少必要条件时，明确说明，允许改看一般饮食、起居内容或寻求专业建议。
5. 收藏饮品，或把符合条件的饮品作为饮食安排的可选补充；饮品不是每份方案的强制组成。

### C. 从身体感受到日常参考

1. 用户可以提出任意健康问题，包括未在首页或专题列表出现的“头痛怎么办”。
2. 已明确紧急时，本轮仅给及时专业求助提示，必要时明确立即急救／急诊；不出任何调养方案、不提供居家医疗处理步骤，不用长问卷延误处理，也不继续执行本轮推荐流程。
3. 其他情况下，按需求澄清发生时间、程度、伴随表现、相关个人情况和希望解决的问题。询问深度随风险变化，不要求每次查完全部病史。
4. 区分知识解释、一般生活调整、需核实的具体食养推荐和专业处理需求；避免把“湿气重”直接判为某种体质或病因。
5. 非紧急、适合生活调整且有依据时，再提供饮食、休息、情绪放松或茶饮参考。基础病患者可获得与已知限制相容的食养解释；特殊人群或情况缺少必要依据时，不生成个人方案，不修改治疗或用药。
6. 资料不足时，仍可解释不确定性、继续澄清或给一般性参考，不因没有专题而拒答，也不为了产出方案编造配方。

### D. 下次继续使用

1. 用户回到“我的”，选择已经保存的方案。
2. 选择“继续调整”，补充“没时间做”“不喜欢”“做不到”等反馈。
3. 助手知道用户选中的是哪份方案、原来如何安排，并提出改动。
4. 用户确认保存更新后替换该方案；只聊天或取消操作不覆盖原方案。

第一版通过用户主动返回和调整来验证重复使用，不加入自动督促、连续打卡或主动消息推送。

## 8. AI 回复的产品要求

每次回复按需要包含：对目标的理解、必要追问、具体建议、推荐内容、适用说明和下一步操作。不强制把每条回答都变成一张方案卡。

### 回答分层：工作建议，尚非经验证的临床分诊规则

分层同时考虑问题内容、个人情况、候选原料和证据充分程度，不能只按年龄或某个关键词判断。风险控制优先；已明确紧急时仅给及时专业求助提示，不等待其他层追问，也不附加调养方案。

| 情况 | 回答方式 | 对具体推荐的约束 |
| --- | --- | --- |
| 一般知识，例如询问某种原料是什么 | 解释传统用途、已有依据与不确定性；按需澄清 | 不必先收集全部个人资料；知识介绍不自动变成“适合你食用” |
| 日常调养需求，相关信息足够 | 结合生活条件给饮食、茶饮、起居或身心调养参考，可形成可修改安排 | 核对具体原料和已知限制；未发现风险不等于已经排除全部风险 |
| 基础病、用药、备孕／孕哺、婴幼儿、高龄、治疗期间或其他特殊情况 | 保守回答有对应依据的一般科普，按需补问或建议医生／药师等核对 | 不一律拒答；必要信息、证据不足或需要专业判断时不生成个人茶方、药材搭配或疾病相关餐单 |
| 明确紧急情况 | 直接及时专业求助，必要时明确立即急救／急诊 | 不生成任何调养方案、推荐卡片、用药或居家处理步骤；不以继续测评或长追问延误求助 |
| 未明确紧急，但明显恶化或需要诊疗评估 | 按适当紧迫程度建议专业评估，可解释需要核对的问题 | 不判断病因，不以食疗或“调理观察”替代评估；无法确认适用性时不出个人方案 |

基础病相关食养有可用的专业资料，例如国家卫健委已发布成人高血压、糖尿病等食养指南；这支持建设相应知识内容，但不等于 AI 已具备独立处理复杂合并症的能力。[指南发布通知](https://www.nhc.gov.cn/sps/c100088/202301/f01895a06c5349ef999f25da833c166d.shtml)

“头痛”示例用于说明产品流程，不据此开茶方或做病因判定。出现突然剧烈头痛、言语或肢体异常等表现时应优先求助；普通生活参考与紧急求助属于不同路径。[NHS 头痛说明](https://www.nhs.uk/symptoms/headaches/)

### 中药知识与具体食用推荐分别约束

中药养生是明确的产品特色。知识内容可以涵盖中药、食药物质、传统食养和身心调养，但把原料推荐给用户自行食用时，需分别核对普通食品、食药物质和药用中药的用途、来源、适用条件与依据。不能因为制成“茶”就默认它是可以自由推荐的普通食品。

中药禁忌是核心约束之一，还包括过敏、药食相互作用、疾病相关膳食限制、年龄与孕哺条件、原料制法及用量范围。国家卫健委对 2023 年新增的党参等九种食药物质明确列出了特殊人群不推荐食用的说明；这里不能外推成所有茶饮都适合或都不适合这些人群。[相关公告解读](https://www.nhc.gov.cn/sps/c100088/202311/a7e49f9f0285437b82b842576fa8ede9.shtml)

十八反、十九畏明确纳入 [中药配伍禁忌规则表](07-中药配伍禁忌规则表.md)。本产品采用保守阻断：命中不推荐，不以少量、间隔或用户自担责任例外放行；核对完整方案及在用中药／中成药成分。未命中仍需检查其他限制，不能将其当成全部安全条件。

药草与药物可能相互影响，且部分组合缺少充分研究。因此“资料库没有查到禁忌”不能等同于“已经证实安全”。[NCCIH 相互作用说明](https://www.nccih.nih.gov/health/tips/tips-how-herbs-can-interact-with-medicines)

已形成独立的 [产品健康规则初稿](05-产品健康规则.md)，记录适用条件、必要追问、可输出内容、限制动作、未知情况处理和证据。它与约束开发流程的 AGENTS.md 不同：规则不仅要可读，还要进入实际推荐校验流程并有测试验证。系统提示词和 RAG 可帮助理解与查证，不能单独证明所有输出可靠；实现依据见技术方案，当前尚未实现规则检查。

### 方案与对话状态

三餐／起居方案至少说清：服务的目标、已经采用的生活条件、分项安排、哪些部分可替换，以及哪些信息仍然未知。不能将“未计算热量”的一般搭配包装为精确减重或增重处方。

助手能使用用户当前对话、主动保存的生活偏好和用户选中的旧方案。进入文章或内容详情后的咨询，应知道对应内容是什么。尚未掌握的信息不得编造，否定表达如“没有过敏”不能仅因出现关键词就被当成相反事实。

输入超出支持范围、服务暂时不可用、内容没有候选或保存失败时，要提供清楚的状态和可执行的下一步。失败的回复不能显示为已经生成或保存成功。

## 9. 体质、档案与内容的首版做法

### 体质

九种基本类型为：平和质、气虚质、阳虚质、阴虚质、痰湿质、湿热质、血瘀质、气郁质、特禀质。市场监管总局的发布说明确认了这九种名称，并说明正式辨识涉及体感问题与等级计分方法。[官方发布说明](https://www.samr.gov.cn/xw/sj/art/2026/art_bbc0d96fbbb741a2a66d2f4f7a44fd82.html)

用户已确认首版包含正式体质测评，题目需要重新设计，同时保留九种体质科普。现有五题和竞品问卷仅为参考，不要求直接沿用任何一套旧题。重新设计包括题目内容、选项、维度覆盖、回溯时间、答题流程，以及相配套的计分与结果解释；题量不预设为五题或照搬竞品。

题目设计应逐项关联专业依据，明确适用人群、计分依据和使用要求，再进行内容审核、可理解性试测与相应测量验证。若对参考量表的内容、题量或计分做实质改动，不能直接沿用其“已经验证”的结论。“作为产品的正式功能”与“问卷的测量性能已经得到验证”分别记录；验证不足时如实标注试测或参考状态，不把算法运行正确当成医学有效性的证明。[问卷内容效度方法参考](https://www.cosmin.nl/wp-content/uploads/COSMIN-methodology-for-content-validity-user-manual-v1.pdf)

首版测评流程包含：查看适用说明、答题、进度与漏答处理、提交计分、结果解释、保存和重新测评。保存结果时记录测评时间、问卷版本、计分版本与验证状态；只有达到预先确定使用条件的结果，才可在用户知情的前提下作为 Agent 的参考信息，不等同于疾病诊断，也不替代禁忌核查。问卷适用依据未覆盖的人群，不强行给出体质结论，但仍可以进行正常健康咨询。

现有五题固定结果只保留为原型参考，不能改名为正式测评，也不进入真实 Agent 的个人信息。已单独形成 [新题目与计分候选稿](04-测评题目与计分设计稿.md)，包括 32 道候选题及描述性计分；题量未定稿，正式判定阈值和适用条件仍需验证。计分采用固定且可复核的规则，并验证样例和边界情况，不由大模型临时出题或自由判分。

### 生活档案

建议首版保存：称呼、关注目标、用餐习惯、饮食偏好和准备时间。避免食材及其他相关限制按具体咨询补问，未确认的信息不默认填“没有”。涉及健康状况的内容不默认作为长期档案保存。

用户已选择 A：在当前浏览器保存生活档案、测评记录、收藏和方案，首版不做产品账号与跨设备同步；清除浏览器数据可能丢失本地记录，需要提前说明。当前托管站点的访问权限与产品账号是两件事。

D3 只实施 A，不同时建设 B。记录留在浏览器与调用云端 Agent 时发送必要信息是两个独立问题，本版仍需数据发送说明，不能宣传为全程离线。

接真实 Agent 后，完成回答所需的输入会发送给服务端／模型服务。届时必须更新当前“未上传服务器”的说明，明确发送哪些信息，并仅发送完成本次咨询必要的内容。不能把本地保存描述成整条咨询链路完全不联网。

### 内容

建议先准备一个小种子集：8 个餐食搭配（早、午、晚各 2 个，另含 2 个加餐）、2 个茶饮、2 个起居参考、6 个调养专题、3 篇短文章和九种体质介绍。数量是用于验证具体内容推荐与替换流程的工作建议，不是 Agent 的提问范围或知识上限。开放问答应同时覆盖知识解释、按风险追问、未知信息处理与适当求助，不依赖每个问题都有预制卡片。

每条用于真实推荐的内容，需要明确出处、具体支持的表述、原料与准备方式、适用条件、审核人和审核日期。传统食养观点与现代营养依据分别标注。不能仅附上一条综合指南链接，就认为某款茶的配方与功效已经被验证。

助手已整理 [首批知识内容与来源](06-首批知识内容与来源.md)，包含可审阅草稿及来源读取状态，当前未有条目完成专业推荐审核。用户可发挥药学背景参与资料筛选和内容复核；超出自身专业范围的内容安排相应专业审核。初期只开放完成审核的条目，无需先建成庞大的知识库或内容管理后台。

## 12. 小范围体验要验证什么

建议先邀请 5–8 位成年人或成年照护者体验不同场景，观察一次完整使用，再在约一周内了解是否主动回来。这只是便于开展的小样本探索，不把产品定位缩成某一成人群体。基础病、孕哺、婴幼儿与紧急问题先用经专业审核的场景验证回答边界，再决定具体推荐能力如何开放；不能以一般人群试用通过来证明所有人群都可安全使用。邀请他人前需另行配置访问权限；当前站点仍仅拥有者可访问。

每人至少尝试：提一个自己的生活目标、修改一次建议、保存一份方案、下次找到并继续调整。记录完成情况、需要帮助的步骤，以及用户觉得省事或不可信的具体原因。

| 验证问题 | 简单记录口径 |
| --- | --- |
| 能不能独立走通 | 完成“提问—修改—保存”的人数／尝试人数，并记录卡住的步骤 |
| 建议是否符合现实 | 用户能否指出一项自己愿意执行的具体安排及其理由 |
| 是否值得再次打开 | 一周内主动返回并查看或调整方案的人数／参与人数；访问不等于健康改善 |
| 相比现有习惯是否省事 | 让用户用自己常用的方法处理同类问题，对比重复输入、整理和修改的困难 |

不预先编造留存或付费目标。首轮先建立基线；如果大多数人需要指导，先修流程；如果能用但没有再次使用的理由，先调整内容与持续使用价值。复盘只记录必要的任务结果和去标识反馈，不默认留存完整健康对话。
