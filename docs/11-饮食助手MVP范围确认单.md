# 知养：饮食助手 MVP 范围确认单

状态：待 linden 审阅。确认后，以本文和 [产品方案](10-饮食助手产品方案.md) 为第一版范围。旧的 [MVP 范围确认单 v0.6](02-MVP范围确认单.md) 保留作对照，其中 D1、D2 不再作为当前第一版的决定。

编写日期：2026-10-03。

## 第一版做成什么样

一个可以在手机浏览器里用的饮食记录助手。用户拍照或打一句话记下吃了什么，看到当天吃得怎样，并得到一道来自知养食谱库的下一餐。

热量是估算，界面写「约」。数字来自食物成分数据，不来自大模型的临场发挥。

## 第一版包含

| 范围 | 做到哪里 | 不做到哪里 |
| --- | --- | --- |
| 记录 | 拍照识别菜品和分量；文字拆成食物和分量；小碗、中碗、大碗一键修正 | 不做专用检测模型；不把估算显示成精确测量 |
| 计算 | 按成分表和克数计算热量与三大营养素；对不上的食物标成无法估算 | 不让模型补数字；不算维生素全表 |
| 当天报告 | 合计、对照参考目标、一两句建议 | 不堆图表；没有记录不编报告 |
| 下一餐 | 只从自有食谱库选择，并说明理由 | 不自由编造菜谱；不自动安排一整周 |
| 风险 | 紧急情况只提示急救；进食障碍、孕期和慢病按产品方案分流 | 不提供治疗膳食和用药建议 |
| 档案 | 改身高、体重、过敏、疾病前先确认 | 不在用户没同意时写入 |
| 保存 | 建议沿用当前浏览器保存 | 账号和云同步未定，见下方决定 |

## 明确不做

商城、问诊、家庭档案、舌诊面诊、穿戴设备、打卡推送、一周自动食谱、自研视觉模型、模型自由编菜。

## 冻结，不从仓库删除

体质测评和九种体质科普、茶饮、调养专题、养生文章、起居示例、以养生咨询为主的模拟对话、十八反和十九畏规则。首页主路径改成记录、报告、下一餐。这些入口可以暂时还在，但不能当作第一版验收的必过项。

## 验收

通过条件就是产品方案里的 B01 到 B10。全部指第一版交付时要达到的行为。现在的原型一条都还不算通过：它没有拍照识菜，也没有成分表计算。

旧确认单里的 A01 到 A15 是养生咨询方向的验收，不转入这一版。其中紧急求助、本机清除、手机可用这几类要求，已经写进 B07、B09、B10，不是整包延后。

## 需要 linden 拍板的决定

下面几项不定下来，实现时会在数据和模型上各做各的。建议写在前面，不是已经生效的决定。

### 1. 用哪家模型

候选、价格量级和接入方式见技术路线。建议第一版视觉和文本用同一家国内服务，个人开发者实名后就能调用。具体选哪一家，需要你定。价格以各家官网当时页面为准，本文只记查阅时的量级。

### 2. 食物成分数据用哪套

候选和授权情况见技术路线。建议：书面授权下来之前，不把《中国食物成分表》整表放进仓库；能用公开许可数据的原料才计算，中国特有食物没有出处就标成无法估算。是否接受这个过渡，以及要不要正式去函申请授权，需要你定。

### 3. 每天的目标从哪来

三个做法：

- 甲：只让用户自己填一个每日热量目标。实现简单，授权风险小。用户不知道填多少时，报告只显示合计，不对比。
- 乙：按《中国居民膳食指南》的公开范围，用性别、年龄段和活动量给出一个建议值，用户确认后才保存。需要确认这段公开表格能不能摘进产品。
- 丙：甲和乙都做。没有确认过的建议值，不写成「你的目标」。

建议用丙。在指南表格的使用方式没有确认前，先按甲上线，避免抄录整张推荐摄入量表。

### 4. 要不要账号和云同步

- 甲：继续不要产品账号。记录在当前浏览器，换手机或清除数据会丢。调用模型时，这一餐的文字或压缩后的照片仍会发给模型服务，这一点要在界面写明。
- 乙：做账号，记录存到服务器，换设备还能看到。要补登录、删除账号和隐私说明，第一版会明显变大。

建议先做甲。照片默认不留在我们的服务器上。

### 5. 食谱库做多大

下一餐只能从库里选，库太小会经常说「没有合适的」。建议第一版 20 道左右家常菜，覆盖早餐、午餐、晚餐，每道写清食材和克数，营养由计算器算出。茶饮不进这个库的推荐候选。数量你可以改。

### 6. 两份旧 PR

建议关闭 #3，不合并 #1。若你希望 #1 的诊断文档进主分支作历史记录，可以另说，本次不把它算进范围。

## 做完的顺序

风险分流从能记录的那一天就挂上，不放到最后。

| 顺序 | 结果 | 还不能声称的事 |
| --- | --- | --- |
| 1 | 成分表小样和计算器，用测试核对几道已知食物 | 还不能记真实的一天 |
| 2 | 文字记录进本机，对不上的食物不产生热量 | 还不能拍照 |
| 3 | 拍照识别加一键改分量 | 报告还没接上 |
| 4 | 当天报告 | 还不会推荐下一餐 |
| 5 | 食谱库和下一餐推荐 | 模型服务和数据源必须已按上面的决定配好 |

模型供应商、密钥和付费调用，等第 1 项决定之后再接。在此之前可以用固定的识别结果把计算和界面走通。
