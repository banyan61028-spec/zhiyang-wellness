# 知养：MVP 范围确认单 v0.1

状态：待确认。这里记录的是建议方案，尚未进入功能开发。

完整依据：[产品设计方案](01-产品设计方案.md)。本单的决定应在用户回复后同步回产品方案。

## 建议的首版形态

保留当前四个页面，做一个可在手机浏览器使用、能够接真实 Agent 的健康养生内测版本。主体验是从生活目标或身体感受进入咨询，查看相关食养内容，修改安排，保存后下次继续调整。

不要求一次补齐完整养生百科；先把少量完成审核的内容和主要使用流程做可靠。

## 首版保留和补齐

| 范围 | 建议保留／实现 | 这版做到哪里 |
| --- | --- | --- |
| 首页 | AI 入口、三餐起居、精选茶饮、调养、文章、档案摘要 | 沿用当前结构，区分一般推荐与结合偏好的建议 |
| 咨询 | 三餐体重、食养茶饮、一般作息、专题内的生活参考 | 能追问、关联具体内容；越界或失败时有下一步 |
| 方案 | 完整三餐及可选加餐、起居安排、单项替换、保存和继续调整 | 真正带入旧方案；不做精确热量、自动一周计划 |
| 食养与内容 | 餐食、茶饮、起居、6 个调养专题、少量文章 | 固定种子集，完成审核的内容才用于真实推荐 |
| 我的 | 目标、生活偏好、收藏、方案 | 建议先在当前浏览器保存；不增加家庭档案 |
| 体质 | 九种基本类型科普 | 正式测评是否纳入见 D2；五题固定示例不作为真实结论 |
| 基本体验 | 手机与电脑可用、清楚的状态反馈、内容来源与数据说明 | 有相关测试与浏览器验证；接真实 Agent 后更新数据发送说明 |

其中最需要补齐的现有差距是：真实对话、完整增重三餐、从旧方案继续调整、可选内容与专业审核、异常处理。当前 Demo 的模拟体质结果不进入真实咨询。

## 请确认三项取舍

### D1：首版 AI 的主要体验

建议：三餐体重与食养茶饮并重。首页保留两类主入口，作息和调养专题也继续存在；首先验证用户能选到具体食养内容，并完成修改与保存。

另一种安排：茶饮与日常调养为主，三餐为辅助。这样主要体验和首批内容审核的顺序会围绕茶饮、身体感受与专题展开。

这项只决定投入优先级，不把产品改成纯减肥工具，也不删除用户希望保留的养生模块。

当前决定：待用户确认。

### D2：正式体质测评是否进入首版

建议：首版提供九种体质科普，正式测评放到下一步。现有五题流程作为设计参考保留在 Demo，退出真实内测版的普通入口，不产生可供 Agent 使用的个人体质结果。

另一种安排：首版就做正式测评。需要在实施前核对正式题目、评分规则、使用条件、来源和结果解释，并增加对应验收；不能沿用五题固定结果作为正式能力。

当前决定：待用户确认。

### D3：首版是否需要账号和跨设备同步

建议：无需产品账号，在当前浏览器保存生活档案、收藏和方案，明确浏览器数据清除后可能丢失。这能继续复用当前体验，先验证产品是否值得用。

另一种安排：首版需要登录并跨设备同步。需要增加登录、账户归属、云端保存和删除等完整体验，对应技术方案与测试范围会扩大。

这项与网站当前的托管访问权限不同；即使不做产品账号，邀请内测用户时仍要配置访问权限。接真实 Agent 所需的数据发送说明，两种方案都必须有。

当前决定：待用户确认。

## 本轮之后再考虑

正式体质测评、云端账号是否提前，按上面的决定执行。其他后续候选包括更多内容、阶段性回顾、内容维护界面和外部工具。

商城、问诊、个性化中药处方、慢病治疗、家庭多人档案、舌诊面诊、穿戴设备、复杂打卡与主动推送，均不放入当前建议范围。
