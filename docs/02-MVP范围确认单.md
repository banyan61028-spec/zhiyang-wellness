## 建议的首版形态

保留当前四个页面，做一个可在手机浏览器使用、能够接真实 Agent 的健康养生内测版本。Agent 以中药养生知识为基础，开放承接各类健康问题，按问题风险、个人情况和知识依据分层回答。适合形成食养安排时，用户可以查看内容、修改、保存并继续调整。

不要求一次补齐完整养生百科；先把少量完成审核的内容和主要使用流程做可靠。

## 已确认的三项决定

### D1：Agent 的定位与回答范围

已按用户本轮澄清更新：

- 产品明确与中药养生挂钩，输出主要围绕食疗、茶饮、起居和整体身心调养。
- 用户可以提出各类健康问题，包括头痛、基础病相关食养以及不同年龄和特殊人群的需求。
- 减重、增重和茶饮是使用示例，不构成问题白名单或唯一目标人群。
- 通过追问与需求澄清，按问题敏感度、个人情况及资料充分程度决定回答方式；不因基础病、孕哺或高龄标签一律拒答。
- 广泛承接问题不等于每次都直接给配方。资料不足时继续解释和澄清；适合食养时给有依据的建议；需要专业处理时优先提示求助。
- 底层需有中药禁忌、药食相互作用、疾病相关限制与特殊人群规则，并在实际推荐中执行。

原来的“三餐体重与茶饮并重／茶饮为主”二选一已撤销，不再等待该选项的回答。首批内容的多少不等于 Agent 的提问范围。

当前决定：定位和开放承接方向已由用户澄清；具体分层规则和实现方案后续细化，不宣称已经验证对所有人群有效。

### D2：正式体质测评是否进入首版

用户已于 2026-09-13 确认：首版做正式体质测评，需要重新设计题目，之前的五题仅作参考，同时保留九种体质科普。

重新设计包括题目内容、选项、维度覆盖、回溯时间、题目顺序，以及对应的计分与结果解释；题量不预设为五题。依据专业资料形成新题目稿并审核、试测。实质修改参考量表后，不能直接继承原量表的验证结论；测评作为正式功能与测量性能的验证状态分开记录。

实施流程包括适用说明、完整答题、进度与漏答处理、规则计分、结果解释、保存与重新测评；按新计分版本验证样例与边界，不由大模型临时出题或自由判分。

当前决定：首版重新设计正式测评；[新题目稿和计分说明](04-测评题目与计分设计稿.md)已单独交付候选版本，正式个人判定仍待验证；旧题仅作参考。记录按 D3 选 A，在当前浏览器保存。

### D3：首版是否需要账号和跨设备同步

用户已选择 A。首版只实施本地保存，不同时开发两套方案。

方案 A（已确认）：无需产品账号，在当前浏览器保存生活档案、测评结果、收藏和方案。更换设备或浏览器不能自动找回，清除浏览器数据可能丢失记录。

方案 B（本轮不做）：账号、云端保存和跨设备同步作为后续候选。

“两种方案都必须有”的意思是：无论选择 A 还是 B，在调用云端 Agent 时，都需要说明会发送哪些提问、档案或测评信息。它是两种选项共有的要求，不是要求同时做两套方案。本地保存档案也不等于 AI 对话全程离线。

这项与网站当前的托管访问权限不同；即使不做产品账号，邀请内测用户时仍要配置访问权限。

当前决定：D3 选 A；无需再在 A、B 之间确认。具体本机存储实现见技术方案。

## 本轮之后再考虑

重新设计的正式体质测评已纳入首版；账号与云端同步暂不做。后续候选包括账号同步、更多内容、阶段性回顾、内容维护界面和外部工具。

商城、问诊、个性化中药处方、慢病治疗、家庭多人档案、舌诊面诊、穿戴设备、复杂打卡与主动推送，均不放入当前建议范围。
