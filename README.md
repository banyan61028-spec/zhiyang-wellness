# 知养 · 健康养生交互 Demo

这是一个以“过日子”为参考的静态交互原型。不是已上线的医疗/健康服务。

## 产品规划

- [产品设计方案 v0.3](docs/01-产品设计方案.md)：依据当前 Demo 和用户决定整理的定位、用户流程、正式测评要求、现状差距与验收要求。
- [MVP 范围确认单 v0.3](docs/02-MVP范围确认单.md)：D1 定位已澄清、D2 正式测评已纳入首版，D3 存储方式待选择。

当前处于范围确认阶段；D1 为中药养生定位、开放健康咨询与分层回答，D2 已确认首版做正式体质测评，D3 尚未选择。技术方案和真实 Agent 接入尚未开始。规划中的目标能力不代表当前 Demo 已经实现。

## 当前能体验

- 首页：AI 入口、健康档案入口、三餐/起居切换、食养推荐、调养话题、文章。
- 模拟咨询：减重、增重、茶饮、作息、排便、咽喉等场景，支持追问、方案保存和替换示例。
- 食养：分类、今日/明日搭配、食谱及饮品详情、收藏、从内容进入咨询。
- 调养：六个示例专题，显示生活建议、适用边界和公开参考来源。
- 档案：生活目标和偏好、本地收藏与方案、九种体质介绍、五题模拟测评流程。

## 真实性边界

- 尚未调用真实大模型、RAG、外部 MCP 服务或任何云端健康数据库。
- `dist/agent.js` 是异步 mock 适配器，输出预设回复。页面可见“模拟对话”标识。
- 五题不是标准量表，所有回答都固定用“平和质”演示结果页，并标明非真实判定。
- 体质名称依据市场监管总局 2026 年发布的 GB/T 46939—2025 说明；未实现标准题目或评分算法。
- 页面所有方案、时间与配图为示例；未计算个人热量/克数，内容未经过完整专业审核。
- 档案、方案和收藏保存在此浏览器的 localStorage；未上传。聊天只保存在页面内存。
- 关键词安全分流仅演示交互，不能视为完整或可靠的医学筛查。
- 图片由 imagegen 生成，详见 assets 来源说明。

## 后续接入自己的 Agent

保持 `getAgentReply({ message, profile, history, scenario })` 接口，改为调用自己的服务端 API。返回结构：`{ scenario, text, choices?, recipes?, plan?, topic?, constitution?, safety? }`。

`plan`：`{ id, title, goal, meals: [{ label, value }], note }`。UI 保存和更新的是返回的结构化对象。`recipes` 和 `topic` 引用 `data.js` 中的合法 ID。

真实上线前应在服务端校验返回字段、内容 ID、计划合理性及适用范围；不能仅信任模型。供应商密钥只放服务端，禁止写入浏览器 JS。食养知识、正式测评及 RAG 可逐项补充，无需改动现有界面流程。

## 文件

- `dist/index.html`：壳层与元信息。
- `dist/styles.css`：响应式界面。
- `dist/app.js`：页面、弹窗、档案、收藏、模拟咨询和方案状态。
- `dist/data.js`：内容示例与公开参考来源。
- `dist/agent.js`：将来可替换的模拟 Agent。

静态服务器从 `dist` 目录启动即可；需 HTTP 服务，因为脚本使用 ES Modules。无外部 JS 依赖。中文字体有系统字体后备。
