# 知养 · 健康养生原型

健康养生产品原型。当前已完成不依赖真实模型的第一轮功能开发；真实 Agent、正式体质判定和专业内容审核仍待后续完成。

## 当前可以体验

- 首页、食养、调养、我的：保留已确认的四页界面、文章、食谱、茶饮示例和九种体质科普。
- 本机档案：生活目标、饮食偏好、收藏、独立方案、多个测评记录和草稿。使用 IndexedDB，刷新后保留，支持清除；不做产品账号或跨设备同步。
- 新测评流程：32 道重新组织的候选题、八类答案选择、返回修改、未答检查、退出恢复和自愿保存。结果整理真实感受，不再固定展示平和质。
- 方案体验：生成预设的完整三餐／加餐示例；保存后打开同一份方案，将鱼类搭配换为豆腐，修订号增加。每份新方案独立保存，并防止过期修订覆盖新记录。起居示例可保存并记录用户自选的准备时间。
- 模拟咨询：服务端 `/api/agent` 已建立。支持预设追问、内容关联、可选饮食偏好、失败重试、取消，以及已知风险示例的保守分流。

## 当前能力边界

真实大模型、RAG 和外部 MCP 均未接入，也没有购买或调用模型服务。自由问题可以输入，但未知问题会明确提示能力未接入。当前预设场景不代表最终 Agent 只能回答这些主题。

新题目和描述性计分尚未完成专业审核与测量验证，不是标准原版问卷；不输出体质分类、概率或健康分，试测摘要不能自动供 Agent 使用。正式测评的产品范围仍保留，最终验收未完成。

健康内容均为待审核示例，不做个人热量计算或个性化草药配方。十八反、十九畏的 12 组初始规则已进入程序，但无完整原料映射、现行药典核对和复方拆解；未命中不等于安全。关键词规则只用于原型验证，不是经过验证的医学分诊能力，也不承诺规避全部责任。

档案和健康记录留在当前浏览器。发送咨询会发送当前问题、有限对话上下文，以及用户主动选择的饮食偏好或当前调整的方案；不发送姓名和原始测评答案。应用服务端不持久化健康记录，不记录问题正文。托管平台自身的日志、保留策略和真实模型的数据条款需要在实际接入时核对。

## 本地开发

需要支持 ESM、Web Request/Response 与内置测试运行器的现代 Node.js。本轮使用 Node 26.8.1。

```sh
npm ci
npm test
npm run build
npm run dev
```

预览地址为 `http://127.0.0.1:8765`。修改后重新构建；服务端模块变更后重启预览服务。无需模型密钥。

源文件在 `src/client`、`src/shared`、`src/server`；新问卷在 `content/questionnaire.json`，初始配伍表在 `rules/herbs.js`。`public` 保存 HTML 与图片；图片来源见 [说明](public/assets/README.md)。`dist/client` 和 `dist/server` 仅存放构建输出，请勿直接修改。

`POST /api/agent` 的结构见技术方案。当前 `src/server/agent.js` 只运行测试替身；以后增加模型适配器时保留前置分流、版本校验和返回检查，不能直接把模型文本当作已审核建议。
