# 知养 · 饮食助手

记下吃了什么，看今天大约吃了多少，再从自己的食谱库里选下一餐。

这一版给身边少数人试用。热量和蛋白质、脂肪、碳水由食物表按「每 100 克 × 克数」计算，界面写成「约」。千问只负责识别食物、估计克数，以及写一两句建议。对不上食物表的，标成「无法估算」，不由模型编一个热量。

体质测评、茶饮、专题和旧的养生咨询还留在仓库里，入口收在「我的」里的「已冻结的内容」，不在主流程上。

## 本地运行

需要支持 ESM 和内置测试运行器的现代 Node.js。

```sh
npm ci
npm test
npm run build
npm run dev
```

预览地址是 `http://127.0.0.1:8765`。手机和电脑浏览器都可以用。没有账号，饮食记录存在当前浏览器的 IndexedDB 里。

`npm run dev` 每次启动都会读取 `data/nutrition` 里的 CSV。改完表格后，先跑校验，再重启预览：

```sh
npm run import-nutrition
npm run dev
```

构建也会先跑同一套校验。格式不对时会逐行报错，不会悄悄跳过。

## 配置千问

模型走阿里云百炼的 OpenAI 兼容接口。密钥只放在环境变量里，不要写进仓库。

```sh
export DASHSCOPE_API_KEY=你的密钥
export DASHSCOPE_VISION_MODEL=qwen3-vl-flash   # 可选，默认识图
export DASHSCOPE_TEXT_MODEL=qwen-plus          # 可选，默认文本
export DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
npm run dev
```

也可以把这些变量写在项目根目录的 `.env`，预览服务会读取。`.env` 已被忽略，不要提交。

没有 `DASHSCOPE_API_KEY` 时，识别、报告和推荐理由使用测试替身，不访问模型服务。文字会按「加、和、逗号」拆开，再拿食物表做精确匹配。例如「中午一碗牛肉面加个蛋」：鸡蛋按本地表计算。牛肉面在本地表里标为不可计算，会按这个名字再问薄荷；没有薄荷密钥时标为无法估算。上传照片在没有密钥时，会返回一份固定的米饭和鸡蛋，方便把后面的计算走通。界面会写明这次是测试替身。

有密钥时，照片和文字会发给阿里云百炼。服务端不把照片和饮食正文写入日志，也不在服务器上保存它们。拍照识别仍走千问，不调用薄荷的图片识别接口。

## 配置薄荷健康

本地 `foods.csv` 能精确匹配、并且该行允许计算时，热量只用本地表。对不上本地表，或对上了但该行标为不可计算（牛肉面、馒头、饺子，以及没有稀粥数据的小米粥、白粥，还有面条、挂面、阳春面），服务端才按这个食物名查询薄荷健康开放平台。「外卖套餐」「套餐」「外卖」太笼统，不查询，界面请用户拆成具体的菜。

```sh
export BOOHEE_API_KEY=你的密钥
npm run dev
```

也可以写在项目根目录的 `.env`，不要提交。代码只从环境变量读取，浏览器拿不到这把密钥。

实际请求是 `GET https://api.boohee.com/open-apis/v1/food/search?keyword=食物名`，请求头 `X-Api-Key`。文档示例里的 `api.iboohee.com` 不要用。返回里每 100 克的热量、蛋白质、脂肪、碳水会记下「薄荷健康」和食物编码，再按克数在本机相乘。同名时优先不带品牌前缀的菜品或食材，例如「番茄炒蛋」而不是「罗森 番茄炒蛋」；其他结果放在候选里，可以改选。

没有密钥、没有搜到、超时或接口失败时，该项显示无法估算，不编数字。查询有十分钟内存缓存，避免同一次试用里重复请求。缓存不写入数据库，也不会按页把薄荷的食物库拉下来。服务端日志只记接口、结果和耗时，不记食物名、饮食正文或密钥。

改完已保存的一餐时，服务端会按食物编码再向薄荷核对这一条，仍然用本地公式算克数。

## 怎么试用

1. 打开首页，写「中午一碗牛肉面加个蛋」，或拍一张餐食照片。
2. 核对食物。分量可以点小、中、大，也可以直接改克数。热量会按食物表重算。
3. 本地表能算的，来源显示「本地食物表」。牛肉面、馒头、饺子、小米粥、白粥、面条这类本地不可计算的名字，配置了薄荷密钥时会显示「薄荷健康」，也可以改选其他候选。搜不到、失败或没有密钥时保持「无法估算」。「外卖套餐」会提示拆成具体的菜，不会去查。
4. 记下来之后，打开「今日」。有记录才有合计。在「我的」里填写并确认每日目标后，才会和目标对比。
5. 下一餐只来自食谱库。不喜欢就换一道。库里没有合适的，会直接说没有，不会新编一道菜。
6. 清除数据在「我的」里，清除前会说明找不回来。

照片和文字会发给模型服务，这句话在记录页、今日和我的页面都写着。

## 导入食物和食谱

表格放在 [`data/nutrition`](data/nutrition/README.md)。食物用 `foods.csv`，食谱用 `recipes.csv`，份量默认值和模型名在 `config.json`。

食物表至少包括：食物名、别名、每 100 克热量、蛋白质、脂肪、碳水、来源、来源备注、版本，以及是否允许计算。食谱不写热量，只写 `食物编号:克数`，多条用竖线分开。

```sh
npm run import-nutrition
```

校验失败会指出文件和行号，例如缺少来源、原料编号不存在、不可计算的原料被写进了食谱。通过后会更新 `src/shared/nutrition/catalog.json`，供没有读到 CSV 时的构建兜底。本地预览仍以 CSV 为准。

仓库里现在的食物仍标着 `example=true`。可计算的原料按 USDA FoodData Central 公开领域数据录入并四舍五入。2026-10-04 增补的无糖豆浆、熟羊肉、芹菜、冬瓜、鳕鱼、四季豆、熟荞麦在 `source_note` 里写了 FDC 编号。没有批量写入薄荷数据，也没有编造热量。煮小米（干饭式）保留 USDA 煮小米的 119 千卡，不再叫小米粥。燕麦粥对得上加水煮软的燕麦，干燕麦不再走这一行。煮鸡蛋面不再充当面条、挂面或阳春面。白粥原先的 46 千卡对不上 USDA，已撤下。这些名字和牛肉面、馒头、饺子一样，记录时再问薄荷。外卖套餐只占位，用来提示拆开。食谱换成 20 道家常草稿，界面角标是「待审核」，审阅清单在 [`docs/14-家常食谱草稿.md`](docs/14-家常食谱草稿.md)。正式采用前请审过再改。

每一条营养数字都带着 `source`、`source_note` 和 `version`。计算代码只依赖「按编号读取食物和食谱」这层接口，以后可以换成别的数据来源，而不改热量公式。

## 边界

- 紧急描述只会提示联系当地急救（中国大陆 120），不会接着给食谱或饮食建议。
- 催吐、绝食、暴瘦、只喝茶，以及已确认的孕期、未成年、肾病、糖尿病、高血压，不会按热量缺口鼓励少吃；肾病不会按蛋白质缺口推高蛋白菜。
- 这不是诊断，也不是治疗膳食。
